# R94 · B — lint, types, build env

## What changed
- **devDependencies (exact):** `eslint 9.39.5`, `globals 17.13.0`, `typescript 5.9.3` (5.x, not 7.0, so `tsc` is the
  stable JS checker). `"lint": "eslint ."` in package.json; lockfile updated.
- **`eslint.config.js`** (flat). Rules: no-undef, no-redeclare, no-dupe-keys, no-unreachable, no-unused-vars
  `{vars:"all", args:"none", caughtErrors:"none"}`, plus `reportUnusedDisableDirectives`. Everything else off.
  - **Load-order globals are DERIVED at lint time, not committed.** The config parses the seven scripts in load order
    (top-level function/const/let/var/class + every `window.X =`). Each script sees all the others' names except its own.
  - `nx/load-order`: errors on a reference evaluated at **definition time** (top level or inside a top-level IIFE;
    `typeof X` exempt) to a name only a LATER script defines. It also errors on a top-level name declared by two
    scripts (a duplicate const/let kills the second script). Probed with doctored stdin copies: both cases fail, and
    call-time and `typeof` references pass.
  - **Gap (documented in the config header):** it does not follow transitive calls. A top-level call to a same-file
    function that touches a later global is missed, and so is a top-level `arr.forEach(fn)` whose callback does.
  - `nx/shared-use`: a top-level name counts as used if another script, `admin/index.html`, or an HTML string in the
    same file (`onclick="fn()"`) names it. no-unused-vars then reports only names nothing can reach.
  - smoke.js and db/check-schema-drift.js get `window`/`document` because their `page.evaluate` callbacks run in the page.
- **`jsconfig.json` + `// @ts-check`** on core.js and site.js only. `include` lists all seven scripts with
  `checkJs:false`, so only the two @ts-check files report errors. Scoping `include` to just those two gives 45 errors,
  because every cross-script global (`db`, `toast` …) goes unresolved. `lib` is `["dom","es2022"]`: naming `lib`
  drops the ES default. Five annotations: two JSDoc casts (`window.db`, the publish button) and three one-line
  `@ts-ignore` above `window.__errorLog` / `__nxTag_core` / `__nxTag_site`. The handshake lines stay byte-identical.
- **build.js:** `SUPABASE_URL`/`SUPABASE_ANON_KEY` come from `process.env` first, with the app.js regex as the fallback.
  The source is logged once to stdout, never the key, so r93_data C17's one-stderr-line rule holds. `SKIP_DIRS` +=
  `docs`, `supabase`, `.github` (CTO addendum: dist/ was shipping `battery.yml`). `SKIP_FILES` += `eslint.config.js`,
  `jsconfig.json`. `tsconfig*.json` is skipped by pattern.
