Deliberately **absent**: `wss://` (no `.channel(`/realtime — app.js says so and A9 asserts it); `blob:` in admin img-src (blob URLs are only CSV/JSON download anchors — navigation, not img-src); `'unsafe-eval'` (A19 static scan + runtime proof: SheetJS executes clean); `google-analytics` (index.html only `dns-prefetch`es it, no script); Trustpilot/FCA/ICO/social (plain links). Opening a storage `signedUrl` in a new tab and `mailto:` are navigations — not governed. The evidence pack is `window.open("")` + `document.write`: an about:blank window **inherits** the admin CSP — it needs only inline `<style>`, `style=` and one inline `onclick`, all allowed (tested).

**Site script-src: `'unsafe-inline'`, not hashes.** Hashes cannot allow inline `on*=` attributes without `'unsafe-hashes'` + one hash per distinct handler (every page has them); a hash list in vercel.json would also have to be regenerated by build.js for every content edit and every rendered guide. And with any hash present, browsers ignore `'unsafe-inline'` — so it is all or nothing. JSON-LD blocks are data, not script-src. Correction to the brief: the site's Google Fonts links have **no** `onload=`; that swap is only in `admin/index.html`.

## Vercel header precedence

Vercel docs (vercel.json → headers): "Unlike routes, continuing to match subsequent headers is the default behavior" — every matching entry applies, in file order. For the same key on the same path the later entry overrides the earlier (stated in the Next.js `headers` docs, same routing engine: "the last header key will override the first"). So `/admin/*` receives the site entry's CSP and then has it replaced by the admin one: the `/admin/:path*` entry must stay AFTER `/(.*)` — test A2 asserts this order. **Not observed live**: the sandbox proxy 403s `nexmoney.co.uk` and the Vercel MCP was denied deployment access. CTO post-deploy check: `curl -sI https://www.nexmoney.co.uk/admin | grep -i content-security` → exactly ONE CSP, the admin one.

## Test — `tests/r94_csp.js`

§A static (24): policy shape/order, no `'unsafe-eval'`/bare `*`/`https:` in script- or connect-src, every external script/stylesheet/img/fetch URL in the source matched by the policy that serves it (this is what covers the real supabase-js tag, which mock.html swaps out), no eval-ish code in shipped JS.
§B runtime (37): the policy is injected as a real **response header** (better than `<meta>`: applies from byte 0, honours frame-ancestors, and is what about:blank popups inherit); only `upgrade-insecure-requests` is stripped (it would upgrade http://localhost). mock.html p1–p4 walking every nav page like smoke.js; a p4 page-script driver opening a case, a client, SheetJS (cdn.sheetjs.com routed to node_modules' build) and the evidence-pack popup; introducer.html; all 18 public pages incl. guides.template.html, each with a fetch to the edge-function host. Asserts zero `securitypolicyviolation` events and zero console "Content Security Policy" messages; network 403s from the sandbox are not violations and are not counted.
**Harness finding:** after any main-world `page.evaluate`, Chrome permits `eval` in that page for good (CDP `allowUnsafeEvalBlockedByCSP`), which would hide a missing `'unsafe-eval'`. The suite therefore never evaluates in the main world: clicks + route-injected page scripts, results read from `<html data-r94-*>`. A control proves an off-policy image and `eval()` ARE caught.
Mutation check (dropped Fonts from admin style-src, Supabase from site connect-src, `data:` from admin img-src): 26 failures, every mutation caught.
