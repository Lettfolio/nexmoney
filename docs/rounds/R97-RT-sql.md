# R97 · Red team · slice **sql** (database layer)

Scope: `supabase/migrations/*.sql` (123 files, later overrides earlier), `db/r84–r95/*`, `db/_live_functions_snapshot.sql`, `db/columns.json`.
Method: I rebuilt the current policy, function and grant state by replaying every `create/drop policy`, `create/drop function` and `grant/revoke` in file order (scripts in the session scratchpad). Then I replayed the two strongest findings on a throwaway local PostgreSQL 16 using the **verbatim** live function and policy text, with a stub `auth.uid()/auth.jwt()` and the role `authenticated`. Nothing touched Supabase.

Roles in the evidence: **adviser** = profile role `adviser`/`staff`. For advisers `session_ok()` is always true, because `mfa_enforced_roles = 'owner,admin'` (`db/r86/01_session_ok.sql:56-58`), so a password alone is a full adviser session.

## Checked and clean

- **TRUNCATE / REFERENCES / TRIGGER** are revoked from anon/authenticated on all public tables and in default privileges (`r84_15_revoke_ddl_privs.sql:5-7`). No later `create table` is outside postgres's defaults; R93 tables re-grant explicitly.
- **RLS is on for all 35 tables** in `db/columns.json`, and `ai_usage` is forced, with no API grant. No table relies on grants alone.
- **anon**: no policy evaluates true for anon except `site_pages` (column-limited) and published `site_posts` (`db/r93/01_site_tables.sql:175,182,197-200`). `get_setting`/`get_setting_on` are invoker functions, so they return null/false through RLS. `session_ok`, `is_*`, `my_introducer_id` and every SECURITY DEFINER RPC are revoked from anon/public (grant history replayed; R94 sweep `01_advisors.sql:7-8`).
- **Role `none`** (fresh signup) can read and update only its own profile. `guard_role_change` blocks changes to `role` and `introducer_id` (`auth.uid() not null and not is_owner()`). The profiles INSERT policy is owner-only, and `handle_new_user` forces `'none'`. Nothing reads `user_metadata`/`app_metadata` for authorisation.
- **Introducer**: `get_introducer_cases/_clients` carry `session_ok()`, use `search_path ''`, are scoped by `my_introducer_id()` (role must be 'introducer'), and are executable only by authenticated (`20261022090000…:69-72`). `get_introducer_clients(p_ids)` can't be steered to other clients (EXISTS on own case). The introducer gets nothing from the other RPCs (each checks role) and nothing from tables beyond its own `introducers` row (`introducers_select`) and own profile. The views are dropped.
- **SECURITY DEFINER functions**: all have a pinned `search_path` (`touch_vault_updated` fixed at `20260828075304…:21`). There's no dynamic SQL in callable bodies; the `execute` calls are one-off migration DO blocks. The 14 caller-path RPCs carry `session_ok()` (live per R86 migration and R94 · D). `queue_*`, `ai_usage_bump` and `queue_lead_ack` are service-role only. `reassign_holdings` is owner + session_ok. `get_reports`/`get_team_mfa` are owner/admin only.
- **settings**: SELECT is owner-only for keys matching `(bank|account|sort_code|secret|token|api|key|password)`, which covers `cron_key` and `vercel_deploy_hook_secret`. INSERT/UPDATE/DELETE are **owner + aal2** only (`r84_12…:116-127`), so an admin can't flip `mfa_enforced_roles`, `email_hold` or `financial_promotions_approved`. The settings audit trail hides values for sensitive keys.
- **case_events**: authenticated can't INSERT/UPDATE/DELETE (no policy; confirmed in the local replay). Every UPDATE path on cases fires `log_case_event`, including the secdef `reassign_holdings`.
- **audit_log**: no write policy, plus an explicit `revoke insert, update, delete` (`audit_log.sql:47`). No FKs, so it outlives deletes.
- **cron / x-cron-key**: the key isn't in the repo (redacted at export, `20260718165010…:13`), it's in Vault for the jobs (`db/r94/01_advisors.sql:116-160`), and staff can't read it (settings regex). It reaches only edge functions; no SQL RPC accepts it.
- **invite-user** is owner + session_ok only, can't mint `owner`, and checks the introducer pointer (`edge/invite-user-v6.ts:43,56-69,93-97`).
- **Views**: only `v_alerts` remains, with `security_invoker = true` re-set after R70's replace (`20260828075304…:9`).
- **Buckets**: `offers`, `client-docs` and `web` are private, and `web` has no policies, so it's service-role only.
