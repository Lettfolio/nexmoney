# R95 · B — app.js has no inline handler

`grep -cE ' on[a-z]+="' admin/app.js` → **0**. `javascript:` in app.js → **0**. Lint 0, tsc 0, smoke 150/150.

## The kit (admin/core.js, fenced `R95 DELEGATION KIT`, installed at definition time)
- `data-act="fn"` + `data-args='[JSON]'`: `"$event"` becomes the event and `"$this"` the element. Missing args → `[]`. The handler is `window[fn]`; a missing fn gives `console.error` once per name and never throws.
- `data-on` = click (default) | change | input | submit | keydown, each with one bubble-phase listener on `document`. Also **error | toggle**: these don't bubble, so they are caught in the capture phase and dispatched only when the target itself carries the act (used by `img.lfav` and `details.brief-fold`).
- The walk from `ev.target` upward runs the nearest `[data-act]` whose `data-on` matches, and stops there (nested acts: closest wins).
- `data-stop` is a click barrier, i.e. the old `event.stopPropagation()`: no outer act runs, and `stopImmediatePropagation()` skips every later document listener (the kit is the FIRST document listener).
- `data-prevent` calls `preventDefault`. `a[href="#"]` clicks and `data-on="submit"` are always prevented.
- Inside the handler, `this` and `ev.currentTarget` are the `[data-act]` element (currentTarget is shadowed via defineProperty, per C's note: toggleDrawer, startRetentionCase and queueEmail read it).
- `actAttr(name, ...args)` returns `data-act="name"` plus `data-args="…"` (attribute-escaped JSON; omitted when there are no args).
- tests/r95_kit.js: 32 checks (substitution, data-on, prevent, unknown name, nesting, data-stop, currentTarget, toggle/error, escaping, app.js clean).
