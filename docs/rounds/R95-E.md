  created_at timestamptz, completed_at timestamptz` FROM cases WHERE `introducer_id IS NOT NULL AND
  introducer_id = (SELECT my_introducer_id())`.
- `v_introducer_clients`: `id uuid, first_name text, last_name text` FROM clients WHERE EXISTS a case with
  `client_id = cl.id` and the same introducer predicate.
- reloptions on both are `{security_invoker=false,security_barrier=true}`, so R94 A was pasted. The ACL is postgres/service_role/`authenticated=r`.
  No other object depends on them (pg_depend). `mfa_enforced_roles = 'owner,admin'`, which does not include introducer,
  so `session_ok()` is true for introducers at aal1. `my_introducer_id()` returns NULL for any non-introducer.
- Function default ACL grants EXECUTE to **anon**, so the explicit revoke is required.
- House RPC ACL (`get_*`): `{postgres, authenticated, service_role}`, no anon.

## RPCs (`supabase/migrations/20261022090000_r95_introducer_rpcs.sql`)
```
get_introducer_cases() returns table(id uuid, client_id uuid, introducer_id uuid, stage public.case_stage,
  case_kind public.case_kind, created_at timestamptz, completed_at timestamptz)
get_introducer_clients(p_ids uuid[]) returns table(id uuid, first_name text, last_name text)
```
Both are `language sql stable security definer set search_path = ''`, fully qualified. The body is the view's own predicate
plus `(select public.session_ok())` and `cl.id = any(p_ids)` for clients. Cases are ordered by `created_at desc`.
SQL-language functions don't need plpgsql/raise. A refusal returns zero rows, exactly what the view gave.
```
revoke all on function public.get_introducer_cases()         from public, anon;
revoke all on function public.get_introducer_clients(uuid[]) from public, anon;
grant execute on function public.get_introducer_cases()          to authenticated;
grant execute on function public.get_introducer_clients(uuid[])  to authenticated;
```
service_role keeps EXECUTE through the default ACL, the same as every other `get_*`. The file does the functions first, then
`drop view if exists` ×2, then a VERIFY block. It has no BEGIN/COMMIT, because none of the 122 exported migrations has one.
Replay on an empty DB works: `my_introducer_id` (20260704190923), `session_ok` (20260908191050) and the views
(20260907191414) all come from earlier migration files.
