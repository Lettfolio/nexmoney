# R95 · A — unsubscribe (report)

Commit `54818d7` on `r95-A`. Nothing deployed.

## Files
- `unsubscribe.html` (new): the `feedback.html` shell with four states (`loading` / `invalid` /
  `confirm` / `done`, toggled with `hidden`), `noindex, nofollow`, and the regulatory footer.
  It has no inline script, no `on*=` attributes and no `javascript:` links. Its only script is
  `<script src="/unsubscribe.js" defer>`. The page copy is v3's wording, unchanged.
- `unsubscribe.js` (new, root, ~45 lines). It reads `?c=&t=`; if either is not uuid-shaped it shows
  `invalid` without making a request. Otherwise it sends `GET {FN}/unsubscribe?format=json&c=&t=`.
  `{valid:false}` shows `invalid`; anything else, including a network failure, shows `confirm`,
  because the POST is what decides. The button sends `POST {FN}/unsubscribe` with JSON `{c,t}`:
  `{ok:true}` shows `done`, `{valid:false}` shows `invalid`, and anything else shows a retry
  banner and re-enables the button. It honours `window.__NEX_FN_BASE`, as feedback.html does.
  Lint passes via a `/* global … */` line, so **eslint.config.js is unchanged**.
- `robots.txt`: `Disallow: /unsubscribe` added to the `*`, GPTBot, ClaudeBot and PerplexityBot
  groups. `sitemap.xml` is untouched. `build.js` is unchanged (the file is copied without minifying).

## unsubscribe v3 → v4 (`edge/unsubscribe-v4.ts`)
- Removed: `escapeHtml`, `page()`, `html()`, `confirmPage()` and the two HTML constants.
- Added: `json()`, `NOT_RECOGNISED()` = `{ok:true, valid:false}`, and `siteUrl()`, which reads
  settings `site_url` with fallback `https://www.nexmoney.co.uk` and strips any trailing `/`.
- GET/HEAD without `format=json` → **302** to `${site_url}/unsubscribe?c=&t=` (values
  URI-encoded). Nothing is read or written apart from the settings row.
- GET `?format=json` → `{ok:true, valid:true}` for a real pair. Bad shape, unknown id, wrong token,
  missing value or an oversized body all get the same `{ok:true, valid:false}`.
- POST (JSON, form or query; RFC 8058 `List-Unsubscribe=One-Click` included) → the same two-flag
  update as v3, answered with 200 JSON `{ok:true}`. A wrong pair gets `{ok:true, valid:false}`.
- Changed from v3: the update's `error` is now checked, and a failed write returns `{ok:false}`
  rather than claiming success. The catch-all also returns `{ok:false}` (still 200, and it reveals
  nothing about the link). The page shows a retry for both.
- Unchanged: the CORS allow-list and `withCors`, the 8 KB cap, the uuid check, `tokenMatches`,
  `readParams` and `lookup`. The header comment was updated in place.
