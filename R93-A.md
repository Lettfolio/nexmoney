# R93 · A — data + edge + build: report

## What I built
- **db/r93/01_site_tables.sql**: the four tables exactly as the contract specifies, plus two indexes (`site_posts(status)`, `seo_snapshots(day desc)`). It also has:
  - RLS on all four.
  - `is_admin_or_owner()` policies in initplan form. site_publishes and seo_snapshots get select/insert/update only: there is no delete policy and no DELETE grant.
  - anon read policies: all of site_pages, and site_posts where status is published.
  - Grants, `site_touch_updated_at()` and the `site_posts_status_guard` trigger. Moving a post into approved or published needs `is_owner()`, otherwise it raises 42501 "Only the owner can approve". It stamps approved_by/approved_at and fills published_at if it is null.
  - The three settings rows, written with `on conflict do nothing`.
  - The whole file is idempotent and wrapped in BEGIN/COMMIT.
- **db/r93/02_cron.sql**: job `nexmoney-seo-snapshot` at `30 2 * * *`, calling `net.http_post` to `/functions/v1/seo-snapshot`. `x-cron-key` is read from `settings.cron_key` when the job runs. The Bearer token is copied out of the existing `nexmoney-process-emails` job's command, and the file aborts if it can't find it. **It has a TODO header** because no live `cron.job` command exists anywhere in the repo.
- **edge/site-publish-v1.ts**: the contract as written, using owner-digest v7's gate (session_ok 403, then role owner/admin, else 401). The hook POST has a 10 s timeout and only https hook URLs are accepted. It returns `{ ok, id, status, detail }`.
- **edge/seo-snapshot-v1.ts**:
  - Who can run it: the cron key, or an owner/admin JWT that passes session_ok. `{ force: true }` overrides `seo_audit_enabled = 'off'`.
  - What it does: sitemap audit (up to 40 pages, 8 at a time) with the contract's issue rules; internal link check (150 cap, HEAD falling back to GET); PSI (15 pages, one after another with a 1 s gap, skipping 429s); GSC (RS256 JWT via WebCrypto from PKCS8; totals, page and query queries, 28 days ending today−2). It then upserts on `(day,kind,page)` and writes the summary.
  - Time limits: one shared 48 s deadline, and every fetch has an AbortController timeout capped by what is left. PSI stops once fewer than 14 s remain. The handler never throws.
- **build.js** (full build only; `--hash` is unchanged and makes no network calls):
  - Fetches site_pages and published site_posts using the anon key read from `admin/app.js`, with an 8 s timeout.
  - Applies the page overrides, FAQ section and FAQPage JSON-LD.
  - Renders guides with `marked@15.0.12`. Raw HTML in the Markdown is escaped, links are limited to https/mailto/relative, then an allow-list pass runs over the output. Writes `dist/guides/<slug>.html` (Article + Breadcrumb JSON-LD, canonical) and the `dist/guides.html` index.
  - Adds `/guides` and the posts to `dist/sitemap.xml`.
  - If anything in the content step fails, it logs one line and the repo HTML ships unchanged.
  - **`NX_CONTENT_FIXTURE=<file.json>`** reads `{site_pages, site_posts}` from a file instead of the network. It is documented in the header.
- **guides.template.html**: faq.html's head, nav and footer with `/`-rooted asset paths. Guides is added to the footer only. build.js skips it from dist.
- **vercel.json**: the `/guides → /faq` redirect is removed. **llms.txt**: Guides line added. **package.json/lock**: `marked` pinned at 15.0.12. I chose 15 because it still ships CJS; marked 16+ is ESM-only.
- **admin/mock-supabase.js**:
  - The four tables, with site_pages keyed by slug, insert defaults and a serial id for seo_snapshots.
  - Write-policy and read-filter parity with the SQL, including the CHECKs, unique slug, the owner-only guard and no delete on snapshots/publishes. The stamping half of the guard and the updated_at touch run on insert, update and upsert.
  - Fixtures: 3 pages; 3 posts (draft, approved, published); 2 publishes; 26 snapshots for yesterday UTC (summary, audit ×14, psi ×3, gsc ×3, gsc_query ×5). The audit issues are worked out with the edge function's own rules.
  - The three settings rows.
  - `site-publish` and `seo-snapshot` edge stubs, both behind the MFA gate. The seo-snapshot stub writes today's set of rows.
  - `functions.invoke` now records `{name, body, at}` into `window.__mockInvokes`. It did not record invokes before.
- **db/columns.json**: the four tables are added, otherwise CI's `db/check-schema-drift.js` would fail on the new mock tables. It passes locally.
- **tests/r93_data.js**: 85 checks.

## How to verify
- `node tests/r93_data.js`: 85 pass, 0 fail. Defaults are REPO = the repo and PORT 8099; I ran it here with `NX_PORT=8134` because other slices are using 8099.
- `node smoke.js` against /root/nx-A on a private port: 150 checks, 0 failures.
- `node db/check-schema-drift.js`: Schema OK.
- `NX_CONTENT_FIXTURE=<file> node build.js`, then inspect `dist/guides*`, `dist/mortgages.html` and `dist/sitemap.xml`. Pointing it at a missing file exercises the failure path.
- `node build.js --hash` prints the same 10 lines as before (the 8 admin files plus style.css and enhance.js).
- seo-snapshot's `auditHtml`, `runAudit` (against a stubbed fetch serving the repo's HTML) and the RS256 assertion were run under Node. The signature verifies with the matching public key. I did not run anything under Deno: deno is not installed, so the edge files were only checked for TypeScript syntax via esbuild.

## Guesses (each one deliberate, please check)
1. **Cron command shape** in 02_cron.sql: Bearer copied from `nexmoney-process-emails`, plus `x-cron-key` from settings and `timeout_milliseconds 60000`. Diff it against `select command from cron.job` before applying.
2. **anon SELECT is column-scoped**. site_pages excludes notes and updated_by; site_posts excludes author_id, approved_by and approved_at. So anon `select=*` returns 42501, and build.js names its columns.
3. **The guard is enforced only for `current_user in ('authenticated','anon')`**, so the SQL editor and service_role are not blocked. The same message, "Only the owner can approve", is used for both approve and publish.
4. **slug `""` maps to `index.html`**, because `"" + ".html"` is not a file.
5. **Override mapping**:
   - og_title also sets twitter:title, og_description sets twitter:description, and og_image (https only) sets twitter:image. title only sets `<title>`.
   - A missing meta tag is inserted before `</head>`.
6. **FAQPage JSON-LD is skipped on a page that already has one** (faq.html), because two on one URL is a Search Console error. The FAQ section is still inserted wherever `<!-- nx:faq -->` exists. No page has that marker today.
7. **Markdown handling**: `#` headings shift down one level (`#` → h2) because the page owns the h1. GFM tables and https images are allowed; a `javascript:` link becomes plain text.
8. **Template placeholders**: I added `{{path}}`, `{{ogtype}}`, `{{ogimage}}` and `{{crumbs}}` beyond the contract's set, and the JSON-LD goes in at `<!--NX:JSONLD-->`. `/guides` is always generated, with "No guides yet." when there are no posts, and always appears in the sitemap. The index page copy is "Mortgage Guides" / "Plain-English mortgage guides from NexMoney's advisers in Bournemouth."
9. **site-publish response codes**: it answers 200 with `ok:false` when the hook itself fails, since supabase-js hides the body of a non-2xx response. It returns 400 only for a missing hook (the contract case) or a non-https hook.
10. **seo-snapshot**:
    - Limits: 40 pages, 6 s per link check, 30 s per PSI call, `category=performance` on PSI. Unreachable links (status 0) are not counted as broken.
    - It audits `https://www.nexmoney.co.uk`, so while the site is gated every page will show `http_error`.
11. **Mock fixtures**: summary has `gsc_connected: true` and `psi_connected: true`, so C must flip them to test the Connect panel. The `site-publish` stub with a hook set answers `201 … PENDING`.
12. **db/columns.json** now lists the four tables before production has them. That is correct once 01 is applied; until then a refreshed snapshot would drop them.
