# R93 · B — Website › Content

## What I built
- **admin/site.js (B fence)** — `loadSiteContent` paints `#page-site-content`:
  - **Publish strip** `#site-pub-strip`: "Last publish <ago> · <who> · <status badge>" (latest `site_publishes`), or
    "Never published"; **Publish site** `#site-publish-btn` (owner/admin) → `db.functions.invoke("site-publish")`,
    toasts "Publish sent" / "Publish failed — <detail>", re-reads the strip. Disabled with title
    "Set the Vercel deploy hook in Settings › Integrations" while `settings.vercel_deploy_hook` is empty.
  - **Pages** `#site-pages-list`: 14 kit rows (`rowItemHtml`) from `sitePagesConst` (sitemap order) merged with
    `site_pages`: path · title override or "— from HTML" · `Desc n` chip (green 70–160, amber 50–69/161–180, red
    otherwise/missing) · "Edited" chip when a row exists. Row click or Edit → `siteOpenPageEditor(slug)`.
  - **Page editor** (`openOverlay`, `#site-page-editor`): title / meta description / H1 / OG title / OG image URL /
    OG description / FAQ q+a rows (add, remove) / internal notes; live counters; Save = `upsert` by slug
    (empty → null, empty FAQ rows dropped, `updated_by` = ME). Cancel/Escape/backdrop with edits →
    `confirmDiscard`; "Keep editing" reopens the editor with what was typed.
  - **Guides** `#site-guides-list` (draft → approved → published → archived, newest first) + `#site-new-guide`.
    Guide editor (`#site-guide-editor`): title, slug (follows the title until edited, or always kept for an existing
    guide; validated against the SQL regex), excerpt (n/200), cover URL, Markdown body with Preview/Write toggle
    (`siteMdToHtml`). Status verbs: Archive (anyone, not on a new or archived guide), Approve (owner, draft only),
    Publish (owner, anything not published). A status verb saves the open edits in the same write. A non-owner's
    draft Save reads "Submit for approval" (same write, status unchanged). Refusals toast the SQL message via `dbFail`.
  - `siteMdToHtml(md)`: `#`–`###`, paragraphs, `**`/`*`, `[t](url)` (https / mailto / relative only), `-`/`*`/`1.`
    lists, `>` quotes; everything escaped first.
  - `siteGuideSetStatus(id, status)` — status-only write (used by the test for the admin refusal path).
- **admin/admin.css** — `/* ===== R93 · B CSS ===== */` fence above the R90 utilities. **Two lines only** (see below).
- **admin/app.js** — Settings › Integrations: one `vercel_deploy_hook` URL input (end of the Integrations panel) and
  its entry in `SETTING_URL_FIELDS` (the save-time "doesn't look like a URL" warning, as review_platform_link has).
- **tests/r93_content.js** — 52 checks (static, owner pages, guides + markdown, publish strip, admin gating, console).

## Guesses
1. Constant is named `sitePagesConst` (the brief's example), not the contract's `SITE_PAGES`. Generic helpers are
   `siteCt*` to keep clear of slice C's `site*` names.
2. Short labels for the 14 pages (Home, Mortgages, First-time buyers, Remortgage, Buy-to-let, …, Share the Love T&Cs).
3. Description chip with no override shows "Desc —" red (we don't know the HTML's own description length); amber band
   50–69 / 161–180 is mine.
4. Title counter tone: green 30–60 (audit's title_short/title_long), amber 20–29 / 61–70.
5. "Submit for approval" = the Save label on a draft for a non-owner (no separate submitted state).
6. Status transitions: Publish allowed from draft/approved/archived for the owner; Archive from any non-archived;
   no "back to draft" verb.
7. URL fields (OG image, cover) accept `https://…` or a site-relative `/path`.
8. Publish failure detail: reads `data.error/detail`, and on a supabase-js `FunctionsHttpError` reads
   `error.context.json()`; the mock returns non-2xx bodies as `data` so both paths are handled.
9. Hook "set" is read from the global `settings` (loaded at init, refreshed by saveSettingsForm). If A or the CTO
   adds `vercel_deploy_hook` to the sensitive (owner-only) settings keys, an **admin** will see Publish disabled even
   though the edge function would work — decide whether the key is sensitive.
10. `#` in a guide renders `<h1>` in the preview (A's `marked` does the same).
