## UNVERIFIED (live-only — the request that settles it)

- **U1 · Is `cf-connecting-ip` client-settable on `*.supabase.co/functions/v1`?** new-lead keys on it first (`new-lead-v5.ts:50`). If the Supabase edge does not overwrite a caller-supplied value, the per-IP cap is bypassable without even racing. Settle: `for i in 1 2 3 4 5 6 7; do curl -s -X POST https://sclghkmvzpwtmnzbkaoe.supabase.co/functions/v1/new-lead -H 'content-type: application/json' -H "cf-connecting-ip: 192.0.2.$i" -d '{"name":"RT97 probe","phone":"0"}'; done` then `select count(distinct source_ip) from leads where name='RT97 probe';` — 7 ⇒ spoofable, 1 ⇒ trusted; then `delete from leads where name='RT97 probe';`. edge-1's DB-side fix closes this either way.
- **U2 · Storage response headers for `client-docs` objects.** A file passes doc-upload's sniff with only `%PDF-` / `ftyp` magic (`doc-upload-v6.ts:83-86`) and is stored with the mapped type (`:184`). Confirm signed-URL downloads carry `X-Content-Type-Options: nosniff` and `Content-Type: application/pdf|image/*`: `curl -sI "<signed url of an uploaded test file>"`. If nosniff is absent, a `%PDF-`-prefixed HTML polyglot could render as HTML in a staff browser on the supabase.co origin (no app cookies there, so impact is low).

## Checked and clean (attempted, held)

- **Token guess space (fact-find / doc-upload / nps / unsubscribe):** all `uuid` v4 via `gen_random_uuid()`/`crypto.randomUUID()` (`migrations/20260718221251…:7`, `20260902210058…:7`, `snapshot.sql:1264`, `process-emails-v22.ts:459`), shape-checked by `uuidRe` before any query; doc/fact-find tokens expire at 30 days (renewed only on a successful send, `process-emails-v22.ts:582-587`). Look-ups filter on the token (index), nps compares in code with `!==`, unsubscribe in constant-time-ish code — remote timing on a 122-bit value is not practical.
- **Enumeration:** unsubscribe answers the same `200 {ok:true,valid:false}` for every bad shape/id/token/oversize (`unsubscribe-v4.ts:69,111,121-123`); nps GET redirects without a look-up (`nps-capture-v5.ts:222-225`); fact-find/doc-upload return `not_found` only for a well-formed but unknown uuid — no oracle worth having.
- **Open redirect / header injection:** both 302s build `Location` from `settings.site_url` (owner-write only, `db/r84/12…:201-212`) plus uuid-validated or `encodeURIComponent`'d values (`unsubscribe-v4.ts:117`, `nps-capture-v5.ts:225`). nps `redirect` field is the settings review link.
- **CORS on the five public functions:** exact `ORIGINS.includes(origin)`; `null`/foreign origin gets `https://www.nexmoney.co.uk` echoed, never reflected; `Vary: Origin` set. Signed-in functions use `*` with bearer tokens (no cookies) — no CSRF.
- **Uploads:** extension whitelist + declared-type agreement + magic bytes (`doc-upload-v6.ts:161-171`); object path is `case_id/slug(item)-ts.ext` — no client filename reaches the key (`:182`); item must belong to the token's case (`:150-152`); single-use per item via `status='requested'` guarded update (`:189-191`); bucket private, read `is_staff()` only (`migrations/20260803114103…:12-18`).
- **Honeypots:** trivially skippable by design (bots that omit the field) — the real guards are the caps (see edge-1).
- **session_ok on signed-in paths:** invite-user, send-sms, owner-digest, outlook-sync, assistant, parse-offer, ai-import, site-publish, seo-snapshot all call `session_ok` through the caller's own JWT before acting — only process-emails is missing (edge-4). invite-user is owner-only and cannot mint `owner` (`invite-user-v6.ts:43,68`); site-publish/seo-snapshot owner/admin; admin/install-web are 410 stubs.
- **Service-role writes beyond caller RLS:** ai-import and parse-offer only return JSON (writes happen client-side under RLS); assistant runs every tool through the caller's JWT client (`assistant-v9.ts:621`), so it cannot exceed the caller's RLS; outlook-sync writes service-role but is owner/admin.
- **Assistant prompt injection:** inbound email subject/snippet, case notes (incl. the public nps comment), briefing email/lead titles and vulnerability notes are wrapped in `<untrusted_client_data>`; forged tags stripped from the client-held history (`assistant-v9.ts:126-139,276-283,293-297`). Unwrapped client names (`search_clients`, `list_cases`) are ≤120 chars each and write tools require the broker's go-ahead — accepted residual.
- **email_hold / fin-promos:** hold checked once before ANY send, both cron and scoped, fail-closed when the row is absent (`process-emails-v22.ts:367-380`); fin-promo types cancelled at send time unless `financial_promotions_approved='on'` (`:436-439`). Marketing opt-out honours both flags with a fresh re-read (`:420-428`).
- **HTML escaping in templates:** every client/lead/case/adviser/settings value in `compose()` passes `escapeHtml` (incl. lead first name, docs items, review link); owner-digest escapes all interpolations (`owner-digest-v7.ts:62-64`). Only `custom` bodies are trusted (edge-3).
- **Secrets:** no key echoed; seo-snapshot redacts `key=` (`seo-snapshot-v1.ts:84-86`); cron key compared against `settings.cron_key`, which non-owners cannot read (regex `key`, `db/r84/12…:206-209`). Error bodies with DB/Graph/Anthropic messages go only to signed-in owner/admin/staff callers. Public functions return fixed strings.
- **outlook-sync tokens:** app-only client-credentials token fetched per run from env secrets, never stored or returned; no per-user refresh tokens exist (`outlook-sync-v6.ts:75-91,210-222`).
