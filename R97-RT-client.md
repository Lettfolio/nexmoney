## Cross-slice notes (not counted here; for the server slice)
- **Adviser "scoping" is presentation only.** As p2 on the mock, `select *` returns clients 50/50, cases 70/70 (with `broker_fee`/`proc_fee`), case_notes 121/121, email_queue 42/42 and audit_log 327/334. That matches prod (`cases read staff` / `clients read staff` = `is_staff()`, R84-10). The "admin sees no fees" rule (`import.js:1818`, `reports-money.js:170`) is also client-only. If the brief's claim that "advisers are scoped to their own cases" is meant as a control, it does not hold. If it is meant as convenience, fine.

## Checked and clean (tried, held)
- **Stored XSS, dynamic.** At page init, every free-text string in every mock table (3,411 values, including vault `fields[]`, `profiles.full_name`, notes, email subjects and bodies, lender names, addresses, appointment titles, site posts and SEO rows) got `"'><i data-x=…>`. I then walked all 15 hashes, every tab, 12 case modals and 12 client modals with folds open, as p4 and p2. **0 injected elements** in both runs, and 171 escaped text hits confirmed the payloads rendered.
- **Static sinks.** `esc` (`core.js:139`) escapes all five characters. `actAttr` passes `JSON.stringify` through `esc` (data-args cannot break out), and no hand-built `data-args` takes dynamic data. Also checked: `kitAttr`/`kitDataAttrs`, `emptyState` (`sub` is escaped; `subHtml` is used only with escaped parts), the list-kit `o.sub`/`o.fact` callers, the assistant bubble (`app.js:25560`, esc before `**`), the evidence-pack `document.write` (`row()` escapes; ids and dates only otherwise), and the `toast` textContent paths.
- **Email preview** (`app.js:21249`): DOMParser, then an allow-list rebuild with **no attributes**, and links flattened to text. Safe, and it neutralises `data-act` too.
- **Import.** AI-row preview, Revolution header/mapping/diff tables, paste parser and date cells are all escaped (`import.js:695-722,1756-1830,315-341`). The offer-PDF and fact-find diff `disp()` helpers escape (`app.js:18571,16159`).
- **Website markdown.** The admin preview `siteMdToHtml` escapes first, allows only https/mailto/relative hrefs, and the admin CSP blocks `javascript:` anyway. The public build (`build.js:225-271`) uses marked with HTML disabled, a tag/attribute allow-list and `safeHref`. JSON-LD goes through `jsonForScript`, and slugs pass `SLUG_RE` before reaching a dist path (no traversal).
- **Introducer page.** Besides the two RPCs it reads only its own `profiles` row and its own `introducers` row (policy `id = my_introducer_id()`). Output is escaped, and `stage` is enum-only.
- **Page gate by URL hash.** As p2, `#money`, `#operations`, `#website`, `#data` and `#emails` redirect to `#today`. `#settings`, `#vault` and `#reports` open by design. The reads behind the gated pages are refused by RLS on the mock: site tables 0/3, seo 0/27, commission tables owner-only, sensitive settings keys hidden (48/53).
- **2FA.** `enterApp` calls `session_ok()` before `showApp`. When the RPC fails it falls through to the app, but RLS still refuses the data. I found no break-glass hints in the UI.
- **Service worker** (`sw.js`): same-origin `/admin/*` GET only, so Supabase API responses (cross-origin) are never cached. Admin HTML has no data in it, and redirects and errors are not cached. The build-tag handshake reloads once, then stops (`app.js:3576-3595`).
- **CSV formula injection** (R46): all three emitters (`exportCsv`, the clients CSV and `miCsv`, which change-history also uses) apply `/^[=+\-@\t\r]/ → '`. No regression.
- **Bulk selections** (pipe, client, ret, prot, email, sms, dh, wt): each is pruned to the rendered set on every repaint, so no bulk verb acts on hidden rows. `openCase` is race-guarded (R83).
- **Money arithmetic.** Every percentage and average division in `reports-money.js` is zero-guarded or falls back to "—", bar widths use `Math.max(...,1)`, and `fmtM` renders null/NaN as "—". Month bucketing uses Europe/London `localMonthStr`, and date-only values are read with `getUTC*` (BST-safe).
- **Storage.** The `nx_*` localStorage keys are UI preferences, scoped per user where it matters. The firm export withholds `*token` columns.
